# お問い合わせフォーム メール送信設定メモ

> **状態：コード実装済み（A: Web3Forms 方式）。残りはアクセスキー登録のみ。**
> 状況ヒアリングの結果（独自ドメインなし／自動返信は今は不要／件数は月数件〜数十件／差出人表示は気にしない）から、**A（Web3Forms）が最適**と判断し実装済み。
> あとは Web3Forms で受信用メアドを登録してアクセスキーを発行し、`NEXT_PUBLIC_WEB3FORMS_KEY` に設定すれば稼働する（→ 後述「稼働させるために残っている作業」）。
> 対象：株式会社WOWNER コーポレートサイトのお問い合わせフォーム（`src/app/ContactForm.tsx`）

---

## 稼働させるために残っている作業（これだけ）

1. https://web3forms.com/ を開き、**受け取りたいメアド**（Gmail等でOK）を入力 → 届いた**アクセスキー**を控える（無料・1分）
2. アクセスキーを設定する：
   - ローカル：`.env.local` の `NEXT_PUBLIC_WEB3FORMS_KEY=` に貼る
   - 本番（Vercel）：プロジェクトの **Environment Variables** に `NEXT_PUBLIC_WEB3FORMS_KEY` を同じ値で登録 → 再デプロイ
3. フォームからテスト送信し、登録メアドに着信することを確認

> ※ キーが未設定の間は、送信時に「送信設定が未完了です」と表示され、誤送信や無言の失敗にならないようガードしてある。

### 後から「自動返信」が欲しくなったら
→ B（Resend）へ移行。`src/app/api/contact/route.ts` を作り Resend 経由で受信＋送信者への自動返信を実装する。改修はフォームのPOST先を差し替える程度で局所的。

---

## 現状（なぜ今は届かないか）

`src/app/ContactForm.tsx` の送信処理は現在これだけ：

```jsx
onSubmit={(e) => {
  e.preventDefault();
  alert("送信ありがとうございます。");
}}
```

→ 「送信ありがとうございます」のポップアップを出すだけで、**入力内容はどこにも送られていない。**

---

## 大前提（クライアント説明用・超重要）

- **メアドをコードに書くだけでは届かない。**
- Webフォーム（ブラウザの入力欄）には**メールを送る機能がない**（なりすまし・迷惑メール防止のためブラウザは直接メール送信できない）。
- メアドはあくまで「**宛先**」。それとは別に「**送信する仕組み（メールを配達する土管）**」が必ず要る。

```
フォーム入力 →  ［送信する仕組み］  → 指定メアドに届く
              ↑ここを用意する必要がある
```

- よって「他のツール/サービスを経由してそのメアドに届くようにする」が正解。
- **必須は2点セット：①宛先メアド ＋ ②送信サービス（土管）**

## 方式の選択肢

| | 方法 | 手間 | 特徴 |
|---|------|------|------|
| **A** | Web3Forms（**推奨・最速**） | ◎ 数分 | 送信先メアドを登録しアクセスキーを発行するだけ。サーバーコード最小・DNS不要・無料枠あり |
| **B** | Resend + Next.js APIルート（Vercel推奨・本格） | △ | 自社ドメイン差出人・HTMLメール・自動返信まで自在。APIキー＋（独自ドメイン差出人なら）DNS認証が必要 |
| C | Formspree | ◎ | A と同系の外部サービス。無料枠は月50件程度 |
| × | `mailto:` | ◎ | メーラーが開くだけ。UX悪・送信保証なしで**非推奨** |

- **手軽さ優先 → A（Web3Forms）**
- 自社ドメイン差出人・自動返信が欲しい → B（Resend）

---

## 構築再開時の手順（A: Web3Forms ルート想定）

1. **クライアント/ユーザー側**：届けたいメアドで Web3Forms（https://web3forms.com/）に登録 → **アクセスキー**を発行（無料・1分）
2. **こちら側**：`src/app/ContactForm.tsx` を改修
   - `access_key` ＋ 各入力値（name / company / email / phone / category / message）を `https://api.web3forms.com/submit` に `fetch` で POST
   - 送信中ローディング・成功/失敗メッセージ・二重送信防止を実装
   - キーは `.env.local` の `NEXT_PUBLIC_WEB3FORMS_KEY` などで管理（Vercelの環境変数にも登録）
3. 動作確認：テスト送信 → 指定メアドに着信することを確認

### 構築再開時の手順（B: Resend ルート想定）
1. Resend アカウント作成 → APIキー取得（`RESEND_API_KEY` を Vercel 環境変数へ）
2. 差出人を自社ドメインにするなら Resend でドメイン認証（DNSにSPF/DKIMレコード追加）
3. `src/app/api/contact/route.ts`（または Server Action）を作成し、フォーム値を受け取って Resend で指定メアドへ送信
4. `ContactForm.tsx` をその API に POST する形へ改修（バリデーション・成功/失敗表示）
