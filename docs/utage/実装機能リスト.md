## Stage 1：共通土台（2日）

### 1-1. ファネル箱

- [ ] **BO+学び家ファネル**（LINE①用の入れ物）
- [ ] **SARUDEMOファネル**（LINE②用の入れ物）

> **なぜ作る**：今後作るフォーム・シナリオ・決済を整理する入れ物。後でフォームが30個になっても「これはBO用」「これはSARU用」と一目でわかる。
> **作らないとどうなる**：機能が増えた時に何がどのサービス用か見分けつかなくなり、修正時に別サービスを誤爆する事故が起きる。

### 1-2. タグ（12個）

- [ ] **流入タグ**：`source_BO` / `source_SARU` / `source_MANA`
- [ ] **決済タグ**：`paid_BO` / `paid_SARU` / `paid_MANA` / `paid_corp_BO` / `paid_FC`
- [ ] **視聴タグ**：`webinar_watched_BO` / `webinar_watched_SARU`
- [ ] **紹介タグ**：`refer_active` / `refer_top`
- [ ] ※推薦タグ（credit/interest/serious 7個）はPause（作らない）

> **なぜ作る**：タグはUTAGE全体の制御スイッチ。「誰に何を配信するか」「誰に何を表示するか」「誰に何を請求するか」が**全部タグの組み合わせで決まる**。
> **各タグの役割**：
> - `source_*`：どのLPからの流入かを記録 → 流入分析・後で分岐したくなった時の基盤
> - `paid_*`：会員サイトのエリア表示制御 → 買った人だけ該当エリアが見える／買ってない人には後追い購入ボタンを出す
> - `webinar_watched_*`：視聴済み者だけに強い決済CTAを出すため（未視聴者にいきなり決済CTAは時期尚早）
> - `refer_*`：紹介経由の決済を計測してアフィリ報酬を計算するため
>
> **最初にまとめて作る理由**：あとからタグを足すと、既存の配信ルール・表示ルールを全部修正する羽目になる。命名がブレると配信条件も壊れる。**1時間で全部作っておくのが結局最速**。

### 1-3. LINE連携

- [ ] **LINE① 共通公式（BO+学び家）連携**
  - チャネルアクセストークン登録
  - Webhook URL設定
  - 応答モード「Bot」切替
  - 友だち追加→UTAGE反映確認
- [ ] **LINE② SARUDEMO専用 連携**
  - 同上の手順を別チャネルで実施

> **なぜ作る**：LPからのCV先がLINE。LINE経由でしかユーザーと連絡できないので、ここを繋がないと**何も始まらない**。Day 1の山場。
> **2チャネルにする理由**：SARUDEMOは契約金300万円と高額。BO/学び家と同じ自動化LINEに混ぜると個別対応が薄まり離脱しやすい → 専用LINE②で運営チームが個別対応する設計。
> **作らないとどうなる**：LP流入は来てもUTAGE側に何も届かない。シナリオ配信もタグ付与も決済も全部動かない。

### 1-4. 申込フォーム（軽量アンケート）

- [ ] **LINE①用 アンケートフォーム**（3〜4問）
  - Q1.お名前 / Q2.メアド / Q3.興味あるサービス
- [ ] **LINE②用 アンケートフォーム**（3〜4問）
- [ ] **回答→source_*タグ自動付与**ルール
- [ ] **回答→ステップ配信開始**トリガー

> **なぜ作る**：名前・メアドを最初に取らないと、決済時に同じ情報を再入力させることになり離脱要因になる。
> **軽量化の理由**：旧設計の6問は離脱率が高い。3〜4問なら回答率がぐっと上がる。
> **興味あるサービスを聞く理由**：「どのサービスに興味ある人が多いか」を分析するため。**いつでも止められる/拡張できる構造**にしておく（推薦ロジック再開時にここを差替えるだけ）。
> **作らないとどうなる**：決済時に名前・メアド未取得状態 → 決済フォームの入力項目が増える → CV率低下。

### 1-5. 会員サイト（箱だけ）

- [ ] **メンバーサイト本体作成**（ログイン方式：メアド+パスワード）
- [ ] **全会員エリア**（マイページ / 紹介URL欄 / お知らせ）
- [ ] **paid_BO エリア**（条件表示・中身プレースホルダ）
- [ ] **paid_SARU エリア**（条件表示・中身プレースホルダ）
- [ ] **paid_MANA エリア**（条件表示・中身プレースホルダ）
- [ ] **後追い購入ボタン群**（条件表示）
  - 学び家追加：`NOT paid_MANA`
  - 法人作成：`paid_BO AND NOT paid_corp_BO`
  - FC加盟：`paid_BO AND NOT paid_FC`

> **なぜ作る**：決済完了直後に「ここにアクセスしてください」と案内できる場所が必須。買ったのに何も返ってこない状態は不安・離脱・返金リクエストの原因になる。
> **箱だけ最初に作る理由**：実コンテンツ動画はクライアント側の素材待ちになる。**箱だけ先に作っておけば、素材が来たら流し込むだけで完成**するのでクリティカルパスを最短化。
> **タグ条件表示の理由**：BO買った人にSARU専用エリアが見えると混乱する。買ってない人に「学び家追加」ボタンが出るのは正しいが、買った人に同じボタンが出ると鬱陶しい → 鬱陶しさ防止＋アップセルの両立。
> **作らないとどうなる**：決済完了→何も起きない→「お金払ったのに何もない」というクレーム発生。

### 1-6. 決済代行連携

- [ ] **Stripe or Univapay APIキー登録**
- [ ] **テスト決済1回成功**
- [ ] **特商法表記の登録**
- [ ] **プライバシーポリシー登録**
- [ ] **利用規約登録**

> **なぜ作る**：UTAGE自体は決済機能を持たない。Stripe/UnivapayのAPIを介して**実際にお金を動かす**ため必須。
> **Stage 1で済ませる理由**：決済代行が動かないと、後続の決済フォーム（Stage 2-4）を作っても完成しない。基盤を先に通しておくことで、決済フォームを作る都度動作確認できる。
> **特商法・規約の理由**：法律で決済前に必ず表示する必要がある。準備せずに公開すると違法。
> **作らないとどうなる**：決済フォームを作っても1円も処理できない。テスト時点でエラーが出続けて先に進めない。

## Stage 2：BO+学び家 縦串（LINE①）（2.5日）

### 2-1. ステップ配信（LINE①）

- [ ] **あいさつメッセージ**（友だち追加直後の自動配信）
- [ ] **Day0**：アンケートURL送付
- [ ] **Day1**：BO/学び家サービス紹介動画
- [ ] **Day2**：事例・実績紹介
- [ ] **Day3**：決済リンク提示（BO/学び家単独/両方）

> **なぜ作る**：友だち追加直後にいきなり「買ってください」では誰も買わない。**教育（信頼構築）の時間が必要**。
> **短尺3〜4通にする理由**：旧設計の7通は長すぎて途中離脱が増える。3〜4通＋動画なら最後まで読まれやすい。
> **動画含める理由**：テキストだけより**顧問の人柄・声色が伝わる**→信頼度UP→CV率UP。
> **作らないとどうなる**：登録直後の温度感のまま放置 → 興味が冷めて忘れられる → そのまま離脱。

### 2-2. 動画機能

- [ ] **動画アップロード/外部埋込**
- [ ] **視聴ログ計測**

> **なぜ作る**：ウェビナー・ステップ配信・メンバーサイトで動画を使うため**共通基盤として必須**。
> **視聴ログを取る理由**：「どこで離脱してるか」が分かれば動画を改善できる。冒頭3秒で離脱されてるなら掴みを変える、後半で離脱なら冗長な部分をカット、など。
> **作らないとどうなる**：動画を使う全機能（ウェビナー・教育配信・会員コンテンツ）が動かない。

### 2-3. ウェビナー（録画自動配信）

- [ ] **BOウェビナー動画準備**（仮素材OK）
- [ ] **ウェビナー申込フォーム**
- [ ] **日時自動繰返設定**
- [ ] **リマインド3段階**（前日メール / 1時間前LINE / 開始直後LINE）
- [ ] **視聴ページ**（動画埋込+離脱ログ）
- [ ] **視聴後CTA 2系統**（決済へ / 個別面談へ）
- [ ] **視聴完了→`webinar_watched_BO` タグ付与**

> **なぜ作る**：1対多の説明会を**自動化**するため。生で毎回喋らなくていいので、24時間いつでもユーザーに見せられる。
> **申込フォームの理由**：視聴者の名前・メアドを取って後でフォローアップするため。
> **リマインド3段階の理由**：申込しても忘れる人が大半。**3段階リマインドで視聴率が2〜3倍**に変わる。
> **CTA2系統の理由**：「すぐ決済できる人」と「まだ質問あるから面談したい人」の**両方を取りこぼさない**ため。
> **視聴完了タグの理由**：見た人だけに強い決済CTAを送るため。**未視聴者にいきなり決済CTAは時期尚早**で逆効果。
> **作らないとどうなる**：説明会を毎回生でやる手間が消えない。録画しても視聴率が低い。視聴しても次の行動が分からない。

### 2-4. 決済フォーム（BO+学び家関連）

- [ ] **BO月額50,000円フォーム**（サブスク・初月無料）
- [ ] **BO決済の学び家オプ**（チェックボックス・+月1万）
- [ ] **学び家単独月10,000円フォーム**（サブスク）
- [ ] **法人作成スポット10万円フォーム**
- [ ] **決済完了→`paid_*` タグ付与ルール**
- [ ] **決済完了→メンバーサイト自動招待メール**
- [ ] **決済完了→LINEサンクスメッセージ送信**
- [ ] **特商法・利用規約 同意チェック**

> **なぜ作る**：**お金を取る最終ポイント**。ここがちゃんと動かないと売上ゼロ。
> **学び家オプ（チェックボックス）の理由**：客単価UP。「ついでに学び家も」と気軽に追加できるUI。
> **学び家単独フォームの理由**：学び家LP流入者・SARU決済をやめても学び家だけは欲しい人を取りこぼさない。
> **法人作成スポットの理由**：BO会員のSTEP2解放のため。月額とは別の単発決済が必要。
> **タグ自動付与の理由**：メンバーサイトのアクセス制御を**手動でやると会員数増えたら破綻**する。決済完了の瞬間に機械的にタグを貼って即時アクセス権付与。
> **メンバー招待メールの理由**：決済完了したのにアクセス方法が分からないと混乱・クレーム。
> **作らないとどうなる**：1円も売上が立たない。立っても会員サイトに入れない。

### 2-5. 個別面談予約（任意・Zoom手動運用）

- [ ] **予約カレンダー**（平日10-18時 / 30分枠）
- [ ] **事前ヒアリングフォーム**（3問）
- [ ] **予約発生時に運営チームへ通知**（メール or 管理画面通知）
- [ ] **リマインド**（前日・1時間前）
- [ ] **リッチメニュー/ウェビナー視聴後からこの面談へリンク**

> **なぜ作る**：決済前に「**どうしても質問したい層**」を取りこぼさないため。動画やテキストだけだと不安が残る人向け。
> **Zoom URLは手動運用の理由**：UTAGEのZoom自動連携は有償オプション契約が必要。本案件ではコスト最適化のため、運営チームが公式LINEから手動でZoom URLを送付する運用とする（2026-05-09 決定）。
> **事前ヒアリングの理由**：面談前に温度感・課題を把握できると面談時間を有効に使える（30分が60分相当の効果に）。
> **作らないとどうなる**：質問したい層が取りこぼされる／面談調整に運営チームの工数がかかる。

### 2-6. アフィリエイト機能

- [ ] **アフィリ機能ON**
- [ ] **紹介URL自動発行**（?ref=会員ID）
- [ ] **紹介経由決済の計測**
- [ ] **マイページに紹介URL表示**（コピーボタン付）
- [ ] **紹介人数・成果表示**

> **なぜ作る**：既存会員の紹介で**広告費ゼロで新規流入**を作るため。事業のスケール装置。
> **URL自動発行の理由**：全会員に1人ずつ手動でURLを渡すのは無理。最初から全員に発行して即使えるように。
> **マイページ表示の理由**：紹介URLがどこにあるか分からないと使われない。**コピーボタン1つで広めやすく**することが大事。
> **紹介人数表示の理由**：紹介者のモチベーション維持。「3人紹介できた」が見えると次の紹介へ動く。
> **作らないとどうなる**：会員が増えても口コミが拡散しない。紹介者のモチベが上がらず継続的な紹介につながらない。

### 2-7. リッチメニュー（LINE①）

- [ ] **4マスデザイン**（Canva等で画像作成）
  - サービス紹介 / ウェビナー予約 / 個別面談 / よくある質問
- [ ] **UTAGE→LINE配信**

> **なぜ作る**：LINEの「**常時表示メニュー**」。会話画面の下にいつも出ているので、ユーザーがいつでも各機能にアクセスできる。
> **4マス構成の理由**：「次に何できる？」が一目で分かる4つを固定配置 → ユーザーの行動の取りこぼし防止。
> **作らないとどうなる**：ユーザーは過去のステップ配信を遡って見直す必要がある → 面倒くさくて離脱。

## Stage 3：SARUDEMO 縦串（LINE②）（1.5日）

### 3-1. ステップ配信（LINE②）

- [ ] **あいさつメッセージ**
- [ ] **Day0**：アンケートURL送付
- [ ] **Day1**：SARUDEMO紹介動画
- [ ] **Day2**：個別面談予約誘導 + 決済リンク

> **なぜ作る**：SARU専用の教育配信。BO+学び家とトーンが違う（**高単価向け・本気度高い人向け**）。
> **2〜3通と短い理由**：高単価・本気度高い人は早く決断したい。長く教育するより**早めに個別面談へ誘導**する方がCV率が高い。
> **作らないとどうなる**：温度感の高い人を待たせて他社に流れる／放置で離脱。

### 3-2. ウェビナー（任意）

- [ ] **SARUウェビナー動画**（個別面談で代替可・あれば設置）
- [ ] **SARUウェビナー申込フォーム**
- [ ] **視聴完了→`webinar_watched_SARU` タグ付与**

> **なぜ作る**：SARUは個別面談がメイン手段だが、**事前にウェビナーを見てもらえれば面談時間を有効活用**できる。
> **任意にする理由**：BOと違い面談で代替可能なので、優先度は低い。動画素材があれば作る程度。
> **作らないとどうなる**：（致命的ではない）面談時間が長引きがち。

### 3-3. 決済フォーム（SARUDEMO関連）

- [ ] **SARU一括300万円フォーム**（クレカ可）
- [ ] **SARU決済の学び家オプ**（チェックボックス）
- [ ] **LINE②内に学び家単独購入リンク**（取りこぼし防止）
- [ ] **決済完了→`paid_SARU` タグ付与+メンバー招待**

> **なぜ作る**：**SARU契約の最終決済地点**。300万円という大型決済が成立する場所。
> **学び家オプの理由**：SARU契約者が学び家にも興味あった場合の追加売上を逃さない。
> **学び家単独リンクの理由**：「**SARUは高すぎる→でも学び家だけなら**」という層を取りこぼさないため。LINE②に来た人を全員SARUに絞ると機会損失が大きい。
> **作らないとどうなる**：SARU契約が成立しない／興味が薄れた層を取りこぼす。

### 3-4. SARU個別面談（高単価向けの濃い対応・Zoom手動運用）

- [ ] **SARU専用予約カレンダー**（既存とは別枠）
- [ ] **高単価向けの事前ヒアリングフォーム**（やや詳しめ）
- [ ] **運営チームへの通知設定**（個別対応のため）
- [ ] **Zoom URLは運営が公式LINE②から手動送付**（自動連携は不採用）

> **なぜ作る**：300万円の決断は対面（オンライン）で疑問解消しないと買えない。**SARUでは面談はほぼ必須**の運用。
> **専用カレンダーにする理由**：BO面談と混ぜると運営チームが混乱する／SARUは1件あたりの重みが違うので別管理にすべき。
> **詳しめヒアリングの理由**：高単価なので「本気度・支払い能力・期待値」を事前に把握しないと面談で時間を浪費する。
> **運営通知の理由**：SARU面談は運営チームが個別対応するので、予約が入ったら即通知して準備時間を確保。
> **Zoom手動運用の理由**：高単価かつ個別対応比率を上げる方針なので、運営チームが直接コミュニケーションを取りたい場面。Zoom URL送付も含めて手動でやり取りする方が温度感が伝わる（2026-05-09 決定）。
> **作らないとどうなる**：面談から決済までCV率が大きく下がる／運営チームが追いつかず予約が放置される。

### 3-5. リッチメニュー（LINE②）

- [ ] **4マスデザイン**
  - SARUDEMO紹介 / 個別面談予約 / 学び家オプ / よくある質問
- [ ] **UTAGE→LINE配信**

> **なぜ作る**：LINE①と同じ理由。ただし**SARU向けに内容を変える**（個別面談予約を最も目立つ位置に）。
> **学び家オプを4マスに含める理由**：取りこぼし防止の動線として常時表示。
> **作らないとどうなる**：LINE②の友だちが次に何できるか分からない／面談予約への動線が弱い。

### 3-6. FC加盟決済フォーム

- [ ] **FC加盟500万円スポットフォーム**
- [ ] **URLは個別面談後に手動送付運用**
- [ ] **決済完了→`paid_FC` タグ付与+STEP3解放**

> **なぜ作る**：BO会員の最終ステップ（500万円）。BOで段階的にステップを踏んできた人だけが到達できるゴール。
> **手動送付運用の理由**：誰でも買えるとマッチしない人が買って失敗する→クレーム化。**個別面談後に適正者にだけURLを送る**運用で品質を担保。
> **タグ付与でSTEP3解放の理由**：FC加盟後にしか見せたくないコンテンツ（FC本部運営ノウハウ等）を機械的にアンロック。
> **作らないとどうなる**：FC加盟がBO会員の最終ゴールとして機能しない／LTVが頭打ち。

## Stage 4：高度化・拡張（2日）

### 4-1. メンバーサイト中身の本格化

- [ ] **STEP1 個人案件動画**（プレースホルダを実動画に）
- [ ] **STEP2 法人案件動画**
- [ ] **STEP3 FC加盟コンテンツ**
- [ ] **学び家コンテンツ**（月次セミナー / 占い予約 / サークル / イベント）
- [ ] **SARU会員コンテンツ**（起業フルパッケージ / 資金調達）

> **なぜ作る**：箱だけだと「準備中」が続いて会員が不満になる。**実コンテンツが入って初めて価値提供完了**。
> **このタイミングの理由**：Stage 1〜3で動線・決済が動くようになってから、実コンテンツを流し込む方が手戻りが少ない。素材待ちの間も他の機能を実装して全体進捗を止めない。
> **作らないとどうなる**：「お金払ったのに中身がない」というクレーム→返金リクエスト→事業継続不能。

### 4-2. アフィリ報酬自動計算

- [ ] **報酬計算ロジック実装**
  - 単発紹介：3,000円/人
  - BO継続：10,000円/月
  - 法人作成：10,000円/件
  - FC加盟金：契約金の10%
- [ ] **報酬支払いタイミング・方法の運用設計**

> **なぜ作る**：紹介人数が増えると手動計算は追いつかない。**自動化必須**。
> **Stage 4まで遅らせる理由**：紹介者がほぼいない初期は手動運用で十分。会員数が増えて手動が破綻する手前で実装すれば良い。
> **作らないとどうなる**：報酬計算ミス→紹介者からクレーム→紹介プログラムへの信頼喪失→紹介発生率が落ちる。

### 4-3. 推薦タグ運用の再開判断

- [ ] 推薦ロジックを再開するか判断
- [ ] 再開する場合：credit/interest/serious 7タグを追加作成
- [ ] アンケートを6問版に拡張
- [ ] タグ別シナリオ分岐配信を実装

> **なぜここで判断する**：シンプル運用で実データを見て「**タグ別の最適化が必要**」と判断できたら再開。最初から作るより無駄が少ない。
> **再開判断の基準**：CV率が頭打ち／層別の最適化したらCVR改善できそうとデータで見える時。
> **再開しない選択も可**：シンプル運用で十分なCV率が出ていれば、タグの複雑さを足さなくてOK。

### 4-4. ABテスト並走シナリオ

- [ ] **配信文言のAB系統作成**
- [ ] **ウェビナーサムネのAB**
- [ ] **計測・比較ダッシュボード**

> **なぜ作る**：配信文・サムネで成約率が大きく変わる。**データで検証しないと感覚で改善できない**。
> **このタイミングの理由**：本番ユーザーがある程度の数いないとABテストが意味を持たない（統計的に判断できない）。Stage 1〜3で集客して規模ができてから着手。
> **作らないとどうなる**：感覚的な改善にとどまり、CVR向上の余地を逃し続ける。

### 4-5. 2期目自動切替

- [ ] **契約日からの経過日数管理**
- [ ] **1年経過時に月額10万円顧問料へ自動切替**
- [ ] **切替前のリマインド配信**

> **なぜ作る**：BO会員は1年経過で月10万円の顧問料に切替契約。**手動だと忘れる→売上漏れ**。
> **このタイミングの理由**：契約者が1年到達するのは早くてもサービス開始から1年後。それまでに実装が間に合えばOK。
> **切替前リマインドの理由**：いきなり10万円の請求が来ると会員が混乱・解約リスク。事前告知が必須。
> **作らないとどうなる**：1年経過後の自動収益化が動かず、LTVが大きく毀損する。
